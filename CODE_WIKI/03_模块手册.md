### 2. `ashare/`（6 模块，≈483 行）—— A 股确定性特征层
纯计算层：不联网、不读写文件、无 pandas/numpy，同输入必同输出。
模块：`ashare_market`（板块/涨跌停/可执行性）、`ashare_factor_engine`（日线派生因子）、
`ashare_cross_section`（横截面排名）、`ashare_event_engine`（公告/解禁/减持等事件标签）、
`ashare_flow_engine`（资金流/龙虎榜）、`ashare_universe`（硬门槛筛选+可解释排序）。
依赖：`universe → market`（唯一内部边）。红线：缺失保持缺失、不扩大数据语义、规则与数据分离。

### 3. `factors/`（6 模块，≈1,201 行）—— 因子研究
回答「因子值不值得进结论」（怎么算在 `ashare`）。
`factor_registry`（想测 vs 数据可支撑）、`factor_gate`（质量+冗余度准入）、
`factor_validation`（防泄漏横截面验证）、`factor_ic_lab`（IC 检验引擎，739 行）、
`factor_lab`（Phase39 runner）、`factor_blind_test`（Phase45 盲测）。
依赖：`lab → (gate, registry, validation)`、`blind_test → ashare`。

### 4. `pit/`（10 模块，≈1,741 行）—— Point-in-time 正确性
纯函数、不落盘、无网络：缺失≠已知、不做事件自动合成、时间单调性（晚于截止时点=前视，拒绝）。
`pit_integrity`、`pit_universe_builder`、`pit_event_master`、`pit_trading_filter`、
`pit_research_rows`、`pit_fundamentals`（按公告日索引，370 行，**财务不前视的唯一执行点**）、
`pit_quarterly`、`pit_snapshot_store`（499 行）、`statistical_industry`、
`baostock_guard`（`n % 2000 == 0 ⇒ 须复核`，防 baostock 静默截断）。
依赖：`research_rows → trading_filter → event_master`。

### 5. `corporate/`（3 模块，≈444 行）—— 公司行为与复权
`corporate_actions`（分红/送股/配股/拆并 → 后复权因子）、
`corporate_action_provider`（数据源适配+覆盖度审计）、`corporate_action_ingest`（CSV 摄入）。
与 `tdx/` 分工：TDX 给不复权原价，本包给显式复权因子，互不隐式补全。
依赖：`ingest → provider → actions`。

### 6. `tdx/`（3 模块，≈429 行）—— TDX 数据集适配
`tdx_csv_adapter`（单文件全市场 CSV 流式读取）、`tdx_inventory`（9.8M 行级清单统计）、
`tdx_lifecycle`（观测生命周期证据）。红线：原价不复权；观测≠事实（缺 bar 不推断停牌/退市）。

### 7. `fetch/`（8 模块，≈1,362 行）—— L2 数据管道（门面=`data_fetcher.py`）
`transport`（SSL 复用/缓存/令牌桶限流）、`common`（常量/纯函数）、
`quote`（实时行情：东财+腾讯兜底）、`kline`（历史日 K：东财/腾讯/通达信本地，**不复权须标注**）、
`news`（新闻+Crawl4AI 可选增强）、`cli`、`akshare_source`、`fundamentals_source`。
依赖：`transport/common → quote/kline → news → cli`。纯标准库，缺失不补造。

### 8. `track/`（4 模块，≈359 行）—— L3 跟踪闭环（门面=`tracking.py`）
`costs`（成本模型）、`schema`（表结构）、`store`（SQLite 持久化）、
`stats`（命中判定/回填/胜率，口径固定：看多>0 命中、看空<0 命中、中性不参与）。
依赖：`costs/schema → store → stats`。零第三方依赖，回填不到保持 pending。

### 9. `risk/`（8 模块，≈1,076 行）—— 风险与可执行性
决定「能不能做、做多大」。`a_share_risk`（市场环境/ATR/仓位）、`risk_engine`（组合级裁决）、
`risk_budget`（反向波动率加权）、`liquidity`（流动性+动态滑点）、`expert_filter`（286 行，
专家过滤器）、`market_risk_gate`（311 行，市场级风险门）、`valuation_weight`、
`var_calculator`（VaR）。红线：优先真实成交额；不可执行就是不可执行；多限制取严。

### 10. `validation/`（9 模块，≈661 行）—— 回测可不可信
`validation_suite`（PASS/CAUTION/FAIL 合成判定）、`performance`（CAGR/夏普/回撤）、
`benchmark`（含**等权全市场基准** `equal_weight_returns`，纠正基准错配）、
`strategy_validation`（Bootstrap/前向窗口）、`robustness`、`stress_test`、
`phase13_risk`（红队审计）、`health_monitor`、
`multiple_testing`（380 行，DSR/BH-FDR/Bonferroni/MinTRL——30+ 检验未校正时
「至少一个显著」概率 78.5%，多重检验校正唯一入口）。
红线：critical 问题一票否决；输出必带 `not_investment_advice`。

### 11. `alpha/`（2 模块，≈229 行）—— Alpha 假设实验
`alpha_experiment`（单一经济假设检验入口）、`alpha_survival_lab`（存活实验协议，
预登记门槛、证据不足强制 `INCONCLUSIVE`）。

### 12. `stage2/`（3 模块，≈281 行）—— Stage-2 二次加工
`stage2_scoring`（确定性二次排序）、`stage2_enrichment`（资金流/龙虎榜叠加）、
`stage2_ablation`（逐层消融，验证独立增量）。纯历史、无未来函数、不包装成真 Alpha。

### 13. `regime/`（3 模块，≈324 行）—— 市场状态
`adx_router`（273 行）、`regime_validation`、`regime_backtest_report`。
状态判定只用历史时点数据，禁止用今天回填历史。

### 14. `reporting/`（3 模块，≈1,054 行）—— HTML 报告
`report_styles`（CSS）、`report_markdown`（纯函数 md→html）、
`report_generator`（`HTMLReportGenerator`，对外唯一入口）。
红线：**报告不改写结论**，不得把 `INCONCLUSIVE` 渲染成确定表述。

### 15. `notify/`（2 模块，≈240 行）—— 通知
`feishu_notifier`（多维表格写入+消息推送）、`lark_notify`。
失败不阻断主流程；推送不含凭据；超时+重试不无限阻塞。

### 16. `router/`（2 模块，≈108 行）—— 源路由
`provider_router`（行情/基本面源）、`quant_skill_router`（因子/打分技能）。
路由失败必须降级默认源；私有口径不当全局事实。

### 17. `runtime/`（2 模块，≈105 行）—— 运行时
`runtime_env`（路径/日志/配置；状态目录默认外置 `~/.ai-stock-god/`，
环境变量 `AI_STOCK_WATCHLIST_FILE/AI_STOCK_STATE_DIR/AI_STOCK_LOG_DIR` 可覆盖）、
`runtime_profile`（8GB 机器资源画像：限并发、限 token）。**刻意零项目内依赖**。

### 18. `phase62/`（2 模块，≈89 行）—— TDX 指数接入（v4.9 选择性移植）
`phase62_series`（指数序列）、`phase62_tdx_index`（指数元信息）。保留 v4.9 原始口径。

### 19. `tushare_client/`（2 模块，≈121 行）—— TuShare 可选接入
`tushare_provider`、`tushare_ashare_events`。Token 仅经环境变量 `TUSHARE_TOKEN`，
依赖缺失即降级，不阻断主流程。

### 20. `console/`（2 模块，≈254 行）—— 交互 CLI（历史框架）
`display`（终端展示）、`teams`（多 Agent 团队执行器）。本层不做业务判断；
空输入绝不提交；依赖 `teams → display` 单向。
