## 一、一句话定位

A 股量化研究的**收口阶段**项目。核心产出有两件，缺一不可：

1. **已固化的推荐系统**（`tdx_native/`）：读通达信原生 `.day`，每日自动出候选清单；
2. **可追溯的研究证据链**：15+ 项预注册实验 + 3 项诊断，全部有登记与判定。

> ⚠️ 项目自我定性（`AGENTS.md` §1）：**它不是一个"能赚钱的策略"**。
> 五因子信号真实但不可变现（IC t 值 5~12，组合跑不赢等权基准）。

## 二、双闭环结构

```
┌──────────────────────── 生产闭环（每日） ────────────────────────┐
│ 通达信 .day → day_reader → adjust(前复权) → five_factor 打分     │
│   → screen(V1尾部剔除/Top20) → daily_report(V2跳空过滤/风险标签)  │
│   → recommend_{date}.md/json + tracking.csv                      │
│   → backfill(T+1建仓/T+5/T+20收益) → 到期卖出提醒 → 飞书推送      │
└──────────────────────────────────────────────────────────────────┘
┌──────────────────────── 研究闭环（按需） ────────────────────────┐
│ 假设 → XXX_PREREG.md(预注册:口径/判定标准/禁止项)                │
│   → scripts/run_*.py → reports/*.json(原始证据落盘)              │
│   → XXX_VERDICT.md(判定;负面结果同样归档)                        │
│   → reports/EVIDENCE_INDEX.md(证据索引与缺口)                    │
└──────────────────────────────────────────────────────────────────┘
        两条链共享：数据资产(.day/gbbq/names/数据集) 与 治理纪律(AGENTS.md)
```

## 三、分层视图（20 子包 + 根目录）

| 层 | 子包/模块 | 职责 |
|---|---|---|
| **数据层** | `tdx_native/` `tdx/` `fetch/` `pit/` `corporate/` `tushare_client/` `phase62/` | .day 读取、L2 行情管道、PIT 时点正确性、复权因子、可选外部源、指数序列 |
| **因子与筛选层** | `ashare/` `factors/` `stage2/` `alpha/` | 确定性因子、因子准入/IC 验证、二次排序/消融、假设存活实验 |
| **风险与执行层** | `risk/` `validation/` `regime/` | 能不能做/做多大、回测可不可信、市场状态识别 |
| **组合与回测层（根目录）** | `backtest_engine.py` `portfolio_backtest.py` `walk_forward.py` `real_alpha_pipeline.py` `screen_pipeline.py` | 单票/组合回测、前向窗口、认证数据管道 |
| **决策与编排层（根目录，历史框架）** | `agents*.py` `orchestrator.py` `console/` `main.py` `prompt_engine.py` `llm_client.py` | LLM 多智能体（**已退出生产**，见 01 篇） |
| **交付层** | `reporting/` `notify/` `track/` | HTML 报告、飞书通知、L3 跟踪闭环 |
| **治理层（根目录）** | `release_gate.py` `run_ci.py` `credential_scan.py` `tests/` | 发布门禁、本地 CI、凭据扫描、守卫测试 |
| **运行时** | `runtime/` `router/` | 路径/日志/配置（零依赖设计）、数据源路由 |

**结构原则**（DIRECTORY_LAYOUT 实测）：
- **门面模式**：`data_fetcher.py` → `fetch/`、`tracking.py` → `track/`
  （实现下沉、门面保留，下游 `import` 不变）；
- **划包看依赖边不看名字**：高耦合核心（`orchestrator`/`portfolio_backtest` 等）
  刻意留根目录；零出边单例不硬凑包；
- **纯计算层零依赖**：`ashare/` 不联网、不读写文件、不依赖 pandas/numpy。

## 四、固化执行配置（改之前先想清楚）

```
C20 分散（top_n=20） + V1 尾部剔除（剔除当日 ret20 最高 20%）
+ V2 跳空过滤（近 21 根内含超涨跌停跳空则剔除）
+ 前复权（基于 gbbq 权息事件） + ST 剔除 + 持有 20 个交易日 + T+1 开盘建仓
```

- 持有 20 日为实测最优（60 日 −3.53pp）；V1 +4.27pp、V2 +3.12pp（均为结构改善，
  **不是新因子**）。这是全项目唯一"敢固化"的配置（`AGENTS.md` §3）。

## 五、治理纪律（架构的组成部分，不是附加品）

| 纪律 | 内容 | 执行点 |
|---|---|---|
| 2.1 不宣称 alpha | 任何输出不得声称超额收益/给投资建议 | 报告层不得软化 `INCONCLUSIVE` |
| 2.2 先预注册后实验 | 口径与登记不符的结果一律作废重跑 | `*_PREREG.md` 先行 |
| 2.3 负面结果归档 | 项目一半以上资产是负结论 | VERDICT 留存 |
| 2.4 数字须可追 | JSON 先落盘才允许写结论；冒烟夹具数字永不作证据；引用必须追到 `reports/*.json` 字段 | `reports/EVIDENCE_INDEX.md` + 守卫测试 |

**守门机制**：`run_ci.py`（syntax/ruff/mypy/compat/pytest/credentials 六步）、
`release_gate.py`（发布门禁 + 幸存者审计）、`tests/`（1,200+ 项，
含「守卫的守卫」如 `test_experiment_status.py`、`test_mailbox_integrity.py`）。

## 六、关键设计取舍（为什么长这样）

1. **通达信原生 `.day` 为主数据源**：本地、免费、含全市场；代价是需自解析
   32 字节二进制（`<IIIIIfII`，价格÷100）并自建复权（gbbq 事件）。
2. **核心管道纯标准库**：`fetch/`、`track/` 零第三方依赖 → 8GB 老机器可跑、
   可单测全覆盖；第三方（crawl4ai/tushare/pandas）全部为**可选降级**。
3. **过滤器互相覆盖的教训已写入架构**：V1 覆盖涨停剔除、1 亿门槛覆盖次新/
   小市值、`min_rows=504` 再覆盖一层 → 新过滤器必须先做「作用对象检查」，
   且须分年代做（`AGENTS.md` §8）。
4. **门槛即干预**：筛选变量与因子共享同一量时（如按成交额筛选再检验
   amihud/loga20），构成循环论证——这是跨年代验证（H-CD）的核心教训。
5. **双 AI 协作 = 架构的一部分**：主干/副本两库 + 信箱协议 +
   「跨侧断言必须在对象所在侧执行命令」——用结构防单点误判（详见 07 篇）。
