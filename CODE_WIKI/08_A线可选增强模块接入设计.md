## 一、为什么是「可选增强」而不是「合并」

01 篇已定性：A 线（`ai-stock-god` 系）与主干**血统同源、范式相反**。
主干里现在就存着 A 线的全部代码（`agents_*` / `orchestrator` / `prompt_engine` /
`llm_client`），但 `ENTRYPOINTS.md` §6.1 把它们标为「历史框架，与生产链无关」。

**现状问题**：这批代码处于「既没删、也没角色」的悬空状态——比删掉更危险，
因为后来者可能误用（`ENTRYPOINTS.md` 的判定规则正是为此而设）。

**本设计的目标**：给它一个**有界的正式角色**——可选、只读、不参与裁决。
即：把「死代码」变成「有红线标注的增强模块」。

**为什么不直接合并**：主干铁律 §2.1（不得宣称 alpha）与 A 线产品形态
（推荐股票 + 评分档位 + 胜率）口径直接冲突。合并会污染证据链。
所以正确做法是**能力级接入，结论级隔离**。

---

## 二、核心设计原则：类型级隔离，而非约定式隔离

> 这是本设计最关键的一条。**不能靠"大家记得别用"来保证边界。**

传统做法是写一条规范「augment 的输出不得进入 VERDICT」。这不可靠——
半年后有人 `import` 一下就破了。

本设计要求边界**在结构上不可能被越过**：

| 机制 | 实现方式 |
|---|---|
| ① 路径隔离 | augment 只能写 `reports/augment/`；裁决链只读 `reports/*.json` 顶层与 `reports/EVIDENCE_INDEX.md`——两个目录集合**不相交** |
| ② 字段强制 | 落盘契约 `AugmentNote.claim_tier` 由写入函数**硬编码**为 `"non-evidence"`，不接受调用方传参 |
| ③ 导入隔离 | 守卫测试断言：`augment/` 以外的任何模块**不得** import `augment` |
| ④ 反向断言 | 守卫测试断言：`release_gate.py`、`validation/`、VERDICT 生成路径**不出现** `augment` 字样与 augment 产物路径 |
| ⑤ 失败等价 | 守卫测试断言：augment 抛异常时 `run_daily` 退出码与不带 augment 时**完全一致** |

②+③+⑤ 是「守卫的守卫」——与项目既有 `test_experiment_status.py`、
`test_mailbox_integrity.py` 同一思路。

## 三、三个增强角色（做什么、不做什么）

A 线价值集中在三处。每处都限定为**「读主干产物 → 产出旁注」**。

### 角色 1 · 解释层（Explanation）

- **输入**：`reports/daily/recommend_{date}.json`（主干 Top20 + 五因子得分 + 风险标签）
- **处理**：复用 8 角色提示词（基本面/情绪/新闻/技术/看多/看空/交易员/风控官），
  逐只生成自然语言解读 + 证伪条件
- **输出**：`reports/augment/explain_{date}.json`；日报**仅追加一行链接**，正文零改动
  （Q2 已定，见 §十二）——因此「报告不得改写结论」红线**无需任何例外条款**
- **禁止**：不得改写候选名单、不得调整排序、不得输出"建议买入"类措辞

### 角色 2 · 假设生成器（Hypothesis）★ 最高价值

- **输入**：主干已有的 JSON 证据（IC 表、正交性矩阵、分年代结果）
- **处理**：让 LLM 从**已落盘的负面/无定论结果**中提出新假设
- **输出**：`reports/augment/hypotheses_{date}.json`（候选假设队列）
- **关键**：队列**不直接执行**。必须经人工筛选 → 写成 `*_PREREG.md` → 才走既有研究链
- **频率**：**不挂每日循环**。建议每两周一轮，或"每完成一项实验后一轮"——
  假设是对**已有证据**的反思产物，证据更新频率是"一项实验完成"而非"每日"；
  挂日循环只会产生无人处理的**假设通货膨胀**
- **单轮上限**：建议 ≤5 条，且每条**必须附证伪条件**（强制质量，防灌水）
- **为什么这是最高价值**：它**强化**而非绕过主干纪律 §2.2（先预注册后实验）。
  LLM 在这里是「假设来源」，不是「结论来源」——这正是纪律允许的用法

### 角色 3 · 呈现层（Presentation）

- **输入**：任意 `reports/*.json`
- **处理**：A 线较丰富的多页 HTML / PPT 风格渲染器
- **输出**：`reports/augment/*.html`
- **禁止**：与 `reporting/` 同一红线——**渲染器不得改写结论**，
  `INCONCLUSIVE` 不得被渲染成确定表述（03 篇 `reporting/` 红线）
- **定位**：`reporting/report_generator.py` 的**可选替代**，默认仍用主干渲染器

> **平台移植（`29/phase30` 的 `jq_strategy.py` / `rq_strategy.py`）不属本文范围。**
> 若要做，因子口径必须从 `tdx_native` 重新导出，且需独立预注册（见 01 篇 §3.5）。

## 四、新增包结构：`augment/`

```
augment/                        ← 新增；唯一允许调用 LLM 的包
├── __init__.py                 ← 红线 docstring（隔离规则摘要，与本文 §二 对齐）
├── contract.py                 ← AugmentNote 数据契约 + 强制 claim_tier
├── explain.py                  ← 角色 1
├── hypothesis.py               ← 角色 2
├── render.py                   ← 角色 3
├── llm_gateway.py              ← 统一 LLM 出口（缺配置即降级，不抛穿）
└── cli.py                      ← 命令行
```

**复用而非重写**（重要——避免第二份实现）：

| 复用对象 | 用途 |
|---|---|
| `agents_base.py` + `agents_analysts.py` + `agents_researchers.py` + `agents_decision.py` | 8 角色定义与提示词 |
| `prompt_engine.py` | 数据包注入 + JSON 输出约束 |
| `llm_client.py` | LLM 调用（火山方舟 Doubao，OpenAI 兼容，纯标准库） |
| `data_fetcher.py`（门面） | 取数（只读） |
| `runtime/runtime_profile` | 8GB 机器限并发 / 限 token |
| `runtime/runtime_env` | 状态目录外置 `~/.ai-stock-god/` |

**不得触碰**：`tdx_native/`、`track/`、`validation/`、`release_gate.py`、
`tracking.csv`、任何 `*_VERDICT.md`、`reports/EVIDENCE_INDEX.md`。

## 五、数据契约：`AugmentNote`

沿用 `data_contracts.py` 的溯源思路，但**独立成文件**（不复用 `DataBundle`，
避免 augment 字段渗入主干契约）：

```python
@dataclass
class AugmentNote:
    code: str                      # 标的
    trade_date: str                # 对应主干推荐日
    role: str                      # fundamental/sentiment/news/technical/
                                   # bullish/bearish/trader/risk
    text: str                      # 旁注正文
    input_digest: str              # 输入 JSON 的 sha256（可追，纪律 2.4）
    claim_tier: str = "non-evidence"   # 只读属性，写入时硬编码，不可传参
    model: Optional[str] = None
    prompt_digest: Optional[str] = None
    created_at: Optional[str] = None
```

**`input_digest` 是纪律 2.4 的落地**：任何 augments 旁注都能追回它读的是哪一版
主干 JSON——主干数据重算后，旧旁注会被守卫识别为**过期**。

## 六、接口红线（五条，与 03 篇模块红线同效力）

1. **单向只读**：只读 `reports/` 与 `data/`；**只写** `reports/augment/`。
2. **claim_tier 强制**：落盘即校验；非 `"non-evidence"` 直接拒绝写盘。
3. **不进裁决链**：`release_gate.py` / `validation/` / VERDICT 路径不得 import `augment`。
4. **失败隔离**：LLM 不可用 / 超时 / 返回非法 JSON → 记 warning 并跳过，
   主流程退出码不变（与 `notify/` 同策略：不阻断生产）。
5. **入口登记**：只经 E3 调用（见 §八）；`run_daily` 侧默认**关闭**。

## 七、连接器：在 07 篇 C 表上新增 C8~C10

| # | 连接器 | 通道 | 方向 |
|---|---|---|---|
| **C8** | 解释连接器 | `reports/daily/recommend_{date}.json` → `augment.explain` → `reports/augment/explain_{date}.json` | 主干 → augment（只读） |
| **C9** | 假设连接器 | `reports/augment/hypotheses_{date}.json` → **人工筛选** → `*_PREREG.md` → 既有研究链 | augment → 人工 → 研究链 |

> **C9 是本设计里唯一"向外"的边，且必须经过人工节点。**
> 这是刻意设计：LLM 假设**不允许**自动进入研究链。

## 八、入口：E3 **正式入口**（Q1 已定）

> **Q1 已定**：E3 登记为**正式入口**（写入 `ENTRYPOINTS.md` §二 表，**不是** §六 历史区）。
> 理由：它是**确定性、可重复调用**的正式能力；与 `scripts/run_*.py`
> （研究脚本，运行前**必须先有预注册**）性质不同——E3 不需要预注册，
> 因为它不产出结论，只产出旁注。

```bash
python -m augment.cli explain --date 2026-10-15        # 角色 1（可挂每日）
python -m augment.cli hypothesize --from reports/      # 角色 2（低频，人工触发）
python -m augment.cli render --input reports/xxx.json  # 角色 3
```

`run_daily` 侧挂载（**默认关**）：

```bash
python -m tdx_native.run_daily --with-augment      # 生产尾部追加解释层（角色 1）
```

> 注意：`--with-augment` **只挂角色 1**。角色 2 严禁进每日循环（见 §三 频率说明）。

**必须同步做的两件事**（否则守卫会失败）：
1. 在 `ENTRYPOINTS.md` §二 表中登记 **E3**（该文件明确规定"需要新增正式入口时须在本表登记并说明理由"）；
2. `tests/test_entrypoints.py` 的登记表同步更新——否则守卫测试报「未登记入口」。

## 十一、明确不做（Non-goals）

1. **不用 LLM 做选股决策**——候选名单永远由 `screen.py` 产出。
2. **不让 augment 输出进入 `tracking.csv` / VERDICT / EVIDENCE_INDEX**。
3. **不重构 `agents_*` 框架**——只复用，不改其内部实现。
4. **不在 augment 里重算因子**——因子只来自 `tdx_native` / `factors/`。
5. **不为 augment 单独建数据库**——产物落 JSON，与主干证据落盘方式一致。
6. **不引入新第三方依赖**——复用 `llm_client.py`（纯标准库）。

### 12.2 Q3 · 假设队列筛选责任人（建议）

项目实际是「单人 + 双 AI 工作区」结构，不存在团队。建议**三段式**——
三段性质不同，因此不能由同一方全包：

| 环节 | 建议负责 | 性质 | 理由 |
|---|---|---|---|
| ① 初筛 | **主干侧 AI**（国内版 WorkBuddy） | 机械规则 | 去重；剔除与已有 VERDICT / 预注册重复的；对照 `factors/factor_registry.py` 剔除"数据不可支撑"的。纯规则判断，**单侧自决**符合信箱协议 R1 |
| ② 独立复核 | **副本侧 AI**（海外版 WorkBuddy） | 反向检查 | 防主干侧自筛时"只保留自己容易做的假设"（自利偏差）；与 07 篇双侧交叉验证原则一致 |
| ③ **立项裁决** | **你本人** | **不可外包** | 预注册 = 口径承诺，落盘即消耗真实算力与时间且**永久归档**。这步一旦外包，纪律 §2.2「先预注册后实验」就名存实亡 |

**关键点**：③ **不可外包**。①② 的产出只是**候选**——不写预注册、不进研究链，
因此即使 ①② 长期停摆，队列也只是 JSON 堆积，**不产生任何污染**（§二 隔离机制兜底）。

**节奏**：**低频**——每两周一轮，或"每完成一项实验后一轮"。
理由同 §三 角色 2：假设是**对已有证据的反思产物**，由证据更新频率决定，不由日历决定。

**防膨胀**：单轮 ≤5 条，每条强制附**证伪条件**（不附则不入队）。
