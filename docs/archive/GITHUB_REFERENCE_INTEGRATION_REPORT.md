## 一、本地项目理解（分析结论）

**定位**：8 个 AI Agent（4 分析师 + 2 研究员 + 交易员 + 风控官）协同的 A股分析与选股系统，L1~L4 四层递进（模板对话 → 数据管道+提示词引擎 → 回测闭环 → 全自动 API）。

**核心竞争力（相对参考项目的优势）**：

1. **研究完整性门禁是代码级的，不是文档级的**
   - `survivorship_guard.py`：6 项证据（PIT 股票池 / 生命周期 / 退市历史 / ST 历史 / 停牌历史 / 公司行动）缺一即裁决 `INCONCLUSIVE`，阻断 Alpha 结论发布；
   - `release_gate.py`：把「统计结论」与「可发布结论」分离，避免把"数据不够"误读成"策略不行"。
2. **PIT（时点正确性）体系完整**：`pit/` 包 + `historical_universe.py`，明确不把今天的股票池当作历史股票池。
3. **诚实记录负结果**：README 直接公布基线策略样本外 -23.20%（同期沪深300 +34.32%），定位失败机制为「纯短期动量追高与 A股短期反转效应相悖」，并撤回了不可复现的结论。这是全套体系里最有价值的资产——**证明了门禁真的会咬人**。
4. **因子检验已建立因果闭环**：9 个经济假设因子 IC 检验（`FACTOR_HYPOTHESIS_REPORT.md`），明确解释了策略为何买在负 IC 因子的最差尾部。
5. **通达信本地数据 + sha256 认证数据集**：数据可溯源、可复算。

**已知短板**：成本模型缺过户费；多窗口回测的印花税未按政策生效日分段；市场状态识别（`regime/`）尚未与策略/仓位联动；无实盘通道。

### 3.2 交易结构与执行

| 规则 | 本地项目 | KHunter | 判定 |
|------|---------|---------|------|
| T+1 | 信号 T 日收盘生成 → T+1 开盘成交；当日买入不可卖（`backtest_engine.py` 文档字符串 + `portfolio_backtest.py`） | T+1 检查，T+1 开盘价执行（`trading/backtest_engine.py`「T+1规则：当天买入的股票不能当天卖出」） | ✅ 一致 |
| 涨停不可买 | `open` 且 `low` 均 ≥ 涨停价×0.999 判一字板 → 跳过买入 | 「涨停基因」检查，可配置 `enable_limit_up_check`（默认开启；加仓不做此检查以与实盘运行器一致） | ✅ 同向；本地口径机械可测，KHunter 更贴近实盘运行器 |
| 跌停不可卖 | `open` 且 `high` 均 ≤ 跌停价×1.001 判锁死 → 顺延卖出日（`execution_rules.first_sellable_index`） | **未发现对应处理** | ✅ 本地更强：避免"跌停强平"的乐观假设 |
| 板块分层涨跌幅 | 主板 10% / 创业板·科创板 20% / 北交所 30%，B股显式排除；**优先逐日状态字段，2026 规则口径**（`ashare/ashare_market.py`） | 全库检索未发现按板块分层的涨跌幅实现 | ✅ 本地更强 |
| ST 处理 | 不凭 `is_st` 猜涨跌幅，要求逐日状态字段提供 | 股票**名称字符串匹配**过滤（`name.startswith('ST')`、含「退」字） | ⚠️ KHunter 的名称过滤存在时点偏差（用今天的名称过滤历史）——恰是本地定义的「名称幸存者偏差」 |
| 停牌 | 数据不足不补造；停牌为硬门槛 | 买入前检查当日是否有真实行情数据，无数据（停牌/退市）即跳过，防止用前收盘价兜底 | ✅ 两者同向；KHunter「防前收兜底」细节值得本地吸收 |
| 整手 | `floor(预算/价格/100)*100` | 有按手数回退逻辑（买入金额+费用 ≤ 可用资金不足则回退一手） | ✅ 一致 |

### 3.3 成本口径的一个真实问题（建议修正）

本地多窗口稳健性检验的起点之一是 **2023-07-03**，早于印花税减半生效日 2023-08-28。该窗口内 2023-07-03 ~ 2023-08-25 成交应按 **0.1%** 旧税率计费，之后按 0.05%。当前 `Costs` 是全程单一税率——对 5 个窗口的中位数结论影响极小（卖出税差 0.05%，短期持仓占比低），但**口径上应改为按交易日分段取税率**，才能经得起"规则可配置、结论可追溯"的标准。

## 五、KHunter 中值得结合的模块（按优先级）

### P1 — 立即可做（规则口径修正，纯代码、无数据风险）
1. **成本模型补全**：在 `backtest_engine.Costs` 增加过户费 0.01‰ 双向（沪深两市，出处见 3.1）；同步在 `track/` 成本层对齐。
2. **印花税分段计费**：`Costs` 支持按交易日取税率（≥2023-08-28 为 0.0005，之前为 0.001），保证 2023-07 起点窗口口径正确。

### P2 — 短期移植（设计模式清晰、可单测）
3. **ADX 三档市场状态路由**（`trading/regime_router.py`，187 行，独立无副作用）：全A指数 ADX <20 震荡 / 20-25 萌芽 / ≥25 明确 → 映射选股策略、择时策略、**仓位系数（1.0/0.5/0.3）**、买入执行方式（明确→开盘价；其余→保守委托）。关键机制：连续确认日防抖动、人工覆盖优先、异常回退 disabled 不阻断主流程、**默认关闭**、决策留痕（样本量 ≥1000 才入选规则表）。可与本地 `regime/`、`market_regime.py` 融合，把「策略选择/仓位」从静态变成状态驱动。
4. **增强 VaR 计算器**（`utils/var_calculator.py`）：历史分位 / EWMA(λ=0.94) / 混合三法，数据 <100 点返回 None。可补强本地 `risk/` 包（当前 `risk_engine.py` 仅 1.2KB）。
5. **连续市场温度风控**（`utils/continuous_temp_risk.py` + YAML 场景配置）：连续 2/3/5 日平均温度 → 按优先级匹配场景 → 仓位限制。配置化、可审计，与本地「规则可配置」原则一致。

### P3 — 中期参考（须先过本地检验，不得直接照搬阈值）
6. **五维评分体系**：技术 35% / 资金 35% / 基本面 10%（排雷为主）/ 板块强度 10% / 事件驱动 10%。资金面权重 35% 与本地 `FACTOR_HYPOTHESIS_REPORT` 的量能因子负 IC 结论存在张力——**引入前必须用本地数据重估各维 IC，不允许照抄权重**。
7. **买入前过滤器**（`trading/buy_filter.py`）：20 日低点涨幅 >50% 剔除、开盘涨幅 >4% 上限。方向与本地「尾部剔除实验」一致（都是抑制追高），但 50%/4% 是 KHunter 经验阈值，需在本地 TDX 数据集上重新标定。
8. **停牌防兜底检查**：KHunter「当日无真实行情数据即不下单，防止用前收盘价成交」——一行逻辑，建议直接并入本地组合回测。

### P4 — 数据与通道（finance-quant-skills）
9. **tdxquant 技能**：通达信量化数据获取脚本，与本地 `tdx/` 适配层天然对接。
10. **miniqmt / qmt-strategy 技能**：迅投 QMT 交易接口文档——个人投资者实盘通道，比 KHunter 的 PTrade（多为券商柜台）门槛更低。
11. **akshare / baostock 技能**：现成数据脚本可充实本地 `fetch/` 多源降级体系（本地已有 `public_daily_source.py`）。
12. **实盘桥接架构**（KHunter `trading/ptrade/khunter_auto_trade.py`）：信号文件驱动、当前价偏离信号价 >3% 不买（追高护栏）、滑点只在信号端计一次（避免双重滑点）、9:31 行情到位后执行、盘前重置状态。本地远期做实盘时可整套参照。
