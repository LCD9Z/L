# Phase 33 — 8GB 运行时优化

## 目标
在不牺牲 A 股数据约束、PIT 和交易规则的前提下，降低普通 8GB RAM 电脑的峰值资源和全流程等待时间。

## 已完成
1. 新增 `runtime_profile.py`：`lite / balanced / full` 三档。
2. `balanced` 默认：4 并发、60 日因子窗口、分析师 1800 tokens、研究员 1600、委员会 2200、决策 1800。
3. 前 6 个独立阶段并行；`review_committee → decision_trade → decision_risk` 保持串行。
4. 并发上限强制不超过 4，避免误配置造成 8GB 机器资源压力。
5. `lite` 降低到 3 并发、40 日因子窗口及更小输出预算。

## 为什么有效
真正耗时通常来自网络 I/O 和模型生成，而不是本地因子计算。把 6 个相互独立的 HTTP/LLM 调用从串行改为有限并发，可以明显降低墙钟时间；线程本身的内存成本远低于启动多个本地模型进程。

## 当前边界
- 没有本地大模型常驻进程，因此没有把 8GB 内存浪费在模型权重上。
- Crawl4AI 浏览器是可选组件；启用后应避免同时跑大量股票。
- 当前 `--codes` 多股票模式仍是逐股票运行，下一阶段会做“先量化筛选、后 LLM 精审”的两级流水线，避免对整个市场逐股调用 9 次模型。
