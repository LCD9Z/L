## 静默失效族（本项目最高频的一类坑）

共同点：**验证者与被验证者是同一个对象时，全绿不构成证据。**

1. **读磁盘能通过 ≠ 文件入库**：`reports/` 是白名单制。新建子目录必须补
   `!reports/<子目录>/` 与 `!reports/<子目录>/*` 两条，并跑 `gen_evidence_index.py`
   确认证据份数增加；判定类产物的守卫必须查 `git ls-files`。
2. **能力已实现 ≠ 能力在生效**：`grep 函数名` 只证明它存在；必须再 grep
   **调用方**并排除 `grep -v "^./tests/"`。
   ⚠️ 别用 `grep -v test`——`multiple_testing.py` 文件名含 `testing` 会被自己滤掉。
   实例：DSR/PSR/MinTRL 曾只有 `tests/` 在调、生产零调用
   ⇒ **p 值校正做了，夏普比率校正没做**，而 pytest 全绿。
3. **外部 `.pyc` 顶替本仓库源码**：`__pycache__` 混入外部路径编译的 `.pyc`，
   其头部 `mtime`/`size` 与 `.py` **完全匹配**（整目录复制保留时间戳）
   ⇒ CPython **优先加载外部字节码**，源码被跳过。
   `git status` 完全看不见（`.pyc` 不入库）；唯一外部信号是 traceback 出现 `???`。
   判据：`marshal.loads(pyc.read_bytes()[16:]).co_filename` 必须落在本仓库根下，
   且须**规范化 + 根路径末尾补 `/`**（否则 `trunk_backup` 会冒充 `trunk`）。
   守卫 `tests/test_no_foreign_pyc.py`；清理用 `os.replace()` 移**同盘**目录
   （跨盘 `WinError 17`；宿主安全删除守卫会拦 `os.remove`）。
4. **签名加了参数 ≠ 参数被使用**：加参后函数体可能仍传旧值/None（D-5 实例：
   `_gap_fill_potential(cn_disc)` 体内仍 `resolve_availability(r, None)`
   ⇒ 产出 89% 幻数，单看输出完全「正常」，靠与归档 12.84% 对账抓出）。
   判据：加参后 grep 函数体内该参数名的使用处，或与一个已知数值对账。

## 反向验证（改守卫自身时必做）

- 只验「改完仍绿」不够——那会把**守卫失效**掩盖成全绿。必须植入已知问题，
  确认它**因为对的理由红**。
- **首轮植入「没红」本身就是发现**（PBO 阈值 0.5→0.9 时 P-2b 抓不到，因为它的
  排名只有 0/1 两值）⇒ 遇此情形不要换植入，要补**边界型守卫**（用合成序列钉阈值），
  然后确认新守卫把原植入抓住了。见 `tests/test_data_snooping.py`。
- **「红得不对」也是假红**：植入把 md 结构写坏时红的原因是「解析不出」而非「哈希不符」
  ⇒ 要检查失败输出的特征串，不是只看 rc≠0。
- 假红信号（不构成有效反向验证）：`SyntaxError`（`sed` 把 `\n` 写坏）、
  `No module named pytest`（解释器落在没装 pytest 的环境）、`FileNotFoundError`
  （缺 grep/git）、路径不存在。做法：固定 venv 绝对路径解释器 → 先跑基线必须绿 →
  失败输出里必须出现该守卫的**特征串**。
- 高危写法：非贪婪 `+?` + 可选量词 → 捕获组被压到最短，`子串 in 短串` 恒 False。
- 反向验证还抓到过**判据自身缺陷**（裸 `startswith(str(ROOT))`）——判据也要被验。

## 跨侧与报数

- **跨侧断言须在对象所在侧执行**（对预注册同样适用）：凡引用行号/参数/文件/计数，
  必须标**侧别**并附该侧命令+输出+HEAD；执行方 ≠ 事实采集方时，执行方须自行复测回执差异。
- `git merge` 的 `--ours` = 当前所在分支、`--theirs` = 被合并方，**与谁更新无关**；
  合并脚本/清单必须标注执行侧，「取我方版/取对方版」换侧后整体反转。
- 复核合并结果**看提交，不看暂存区**：`git show <commit>:<path>`。
- 报数必须写**范围 + 计数**（同分母不同口径会给出「都对但互相矛盾」的数）；
  跨侧交接时接收方按自己的范围重数一遍。
- 「数字链自洽」只判**同型**产物：先比键结构与数据源确认同型，再谈权威。

## 工程纪律

- **批量登记逐份自证优先**：先读产物内嵌字段（标 `origin=embedded`），
  缺失才按批推断（`origin=backfilled`），`unknown` 一律不采信。
- **谁更新必须比内容，不能比 size/mtime**：size 差恰等于行数时几乎必然是
  CRLF/LF；先算去行尾 md5 或 `git hash-object`。`git status` 报 M 但 `git diff` 空
  ⇒ 索引 stat 缓存脏，`git add` 刷新即可，不是内容变更。
- 守卫**优先纯 Python**（`Path.rglob`），不 shell out；必须 shell out 时先
  `shutil.which()` 并显式 skip——不可让「环境缺失」伪装成「断言失败」。
- **CI 结论必须带 HEAD + 时刻**：仓库会被并发改动，同一条命令在不同 HEAD 下不可比。
  别越权重生成并发会话的证据链，正确动作是报时间线 + 给修复命令。
- **过程指标必须可由本地留痕复算，否则不写**（会话转录只存 `output_text`、
  不存 tool_use ⇒ 检索条数天生不可复算）。给外部项目打「可信」需
  `README 宣称 → 代码 → 实跑` 三跳；receipt 方案的验收必须包含
  「文档里的哈希由产物算出，不许手写」（收据绑生成器版本，版本一变旧哈希即失效）。
- **全量测试红先分类「代码缺陷 vs 登记缺口 vs 守卫抓对了」**：本轮 6 项失败全是登记缺口
  （PACKAGES 预期清单未列新模块 / `DIRECTORY_LAYOUT.md` 未重生成 / 新测试用了
  守卫禁用的 `import fetch.x` 形态 / 判定文稿半成品），无一代码缺陷。
  新产出落地后先同步四类登记再跑全量，别把登记红当回归、更别改守卫迁就。
  ⚠️ 第三种情形：**守卫抓对了**（删产物键被 F-5 拦）——正确处置是加**显式白名单**
  （`RETIRED_KEYS` + 缺陷号），不是放宽断言。
- **产物里嵌墙钟 ⇒ 字节级复现永远不成立**（`elapsed_sec` 让两次干净重跑唯一差异
  就是它）。收据类机制（A7）必须先清掉这类字段；诊断信息走 stdout，不进产物。
- 交付前过 `AGENTS.md` §11 自省检查；写完后重读，凡「不能用一条命令证明」的
  断言，降级为推测或删掉。
- **文档里列的失败清单默认是「历史」不是「现状」**：`scan_silent_failures.py` 的
