## git push 终于通了（此前两次会话都卡这里）

现象：`schannel: failed to receive handshake, SSL/TLS connection failed`，
但 `curl https://github.com` 返回 200 ⇒ 不是网络封锁，是 **git 自己的代理配置**。

根因：仓库/全局 git config 里写死了 `http.proxy = http://127.0.0.1:10808`
（**优先于环境变量**），而该端口当前**没有监听**；宿主环境变量
`https_proxy` 指向的是另一个可用代理（本次是 `127.0.0.1:60287`，每次会话可能变）。

判据与修法：
```bash
curl -x http://127.0.0.1:10808 -o /dev/null -w "%{http_code}\n" https://github.com   # 不通
git -c http.proxy=$https_proxy -c https.proxy=$https_proxy ls-remote origin           # 通
git -c http.proxy=$https_proxy -c https.proxy=$https_proxy push origin main
```
⇒ 别再把它当网络问题反复重试；**先 `env | grep -i proxy` 拿当前可用代理，用 `-c` 覆盖**。
（不要改全局 config：`10808` 是用户 VPN 客户端的端口，客户端起来后仍应优先用它。）
